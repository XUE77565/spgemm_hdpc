# spec94:同 j 聚合(重行主刀候选)——解析判死于设计期(09-24 02:2x 夜班#1)

链数 ÷13。前科:HASH_WM(warp 级 match_any 聚合)2.1× 劣——本刀定位为"同线程零通信"形态。

## 2. 解析判死(设计期,免实现)

**邻接同 j 不存在(CSR 构造性)**:
- 行内:B 行列号严格递增(CSR 唯一性)→ q-步进线程流内 j 严格递增 → 相邻同 j 恒假;
- 跨 k 边界:线程访问 k 序列 stride=num_groups(32),k₁ 末乘积=该段最大列,
  k₂ 首乘积=该段最小列——两端列,相等概率≈0;
- 非邻接同线程重逢:13 次命中均匀散布在 1024 线程 → 同线程两次概率/列 ≈ C(13,2)/1024
  ≈ 0.078 → 每线程期望重逢 ≈ 8000×0.078/1024 ≈ **0.6 次/行**——寄存器缓存形态也死。

**结论:dup 是跨线程现象,任何 per-thread 聚合(邻接检测/迷你寄存器表)统计上不可行。
聚合必须跨线程 = warp/块级 = WM 家族。**

收集 ≈ 15+ 指令/32 乘积窗)②全 warp 全窗恒掩码同步 ③gnm 循环内派发。
重审方向(desk,未做):SASS 计 WM2 内环真实指令数/窗 vs 裸探测;若固定成本是主因,
更便宜的同 j 检测=lane 间 j 相等的硬件前缀(__reduce_max/min j + 早退)或排序-free
的 bucket 化。列队列后续,非当轮。
