# Ocean vs 我们的 Auto:对比与优劣(小白版)

> 一句话立场:Ocean 赢在**架构**(一层判断、常数有出处、处处适用);
> 我们赢在**弹药**(内核种类多、几个专项机制是真金),输在**决策系统**(一串拟合门)。
> 数字口径:配对双二进制同窗测量(唯一可信口径)。

## 架构对比:决策系统

### Ocean:一次比较

```
span 投影到 SMEM 预算梯 → dense_bin
est  投影到同一条梯     → hash_bin
dense_bin ≤ hash_bin ? 走 dense : 走 hash
```

- 常数全部硬件出处(128KB / 9B/列 / 12B/槽)
- 换 GPU、换矩阵、加内核:规则不变,梯子加一行
- 怪物行也在体系内(largest 全局混合表)

### 我们:一串门

```
ESC门 → LARGEST门 → 小跨度门 → v4主门(flop/est/spanf/occgate/dup 五条件)
→ 地板分治 → §28矩阵级密度门 → §29惰性 → ALEN门 → …
```

- 每道门都是某次电池的赢家,**只在采样过的家族上成立**
- 实测翻车案例:§28 把 sme3Da 送老内核,实际 struct 快 21%;span 门曾把 c-64 的
  老赢家行全部驱逐(+95%);密度门单维版在 in-2004 上 +28ms 灾难
- **两周内单维门四连证伪**——每道门都是"成本模型"的粗糙手写替身

**判定:决策系统 Ocean 完胜,这是我们最大的结构性欠账。**

## 内核对比:单点火力

| 能力 | Ocean | 我们 | 谁强 |
|---|---|---|---|
| dense 位图 symbolic+numeric | ✓(招牌) | ✓ 已学来(六档梯) | ≈ |

因为决策系统不知道什么时候该掏哪件武器。**

## 方法论对比(测量纪律)

这件事上我们付了昂贵学费,换来几条 Ocean 论文里不会写的实操铁律:

1. **小阵(2-8ms)单跑噪声 ±13-25%** → 判 10% 级效应必须 ×5 中位
2. **跨天 CSV 不可比**(机器漂移 ±2%)→ 版本判定只走配对双二进制同窗交替
3. **测量窗口必须全静**——连旁边跑一个 nvcc 编译都会污染 GPU 事件计时
4. **验证集不能包含催生补丁的矩阵**,否则是自我确认(我们最大的教训)

## 劣势根因与收敛路线(共识版)

我们为什么长成一串门?因为内核选项多(三条路 + 五六个专项),每条过渡长出一个规则,
每个规则又长出一个补丁。收敛路线(已定方向):

```
v36 蓝图:三内核 × 足迹成本表 × 一次 argmin
  老内核足迹   ≈ a_len × ⌈span/窗宽⌉ × log₂(avg_B) × 128B(链×窗重扫,物理可推)
  结构内核足迹 ≈ span × 9B(与 Ocean 9B/列同源)
  (待补:人口/发射规模项——第一轮留出验证证伪了纯行级模型,缺口已定位)
```

新内核入列 = 成本表加一行;模型错了 = 修模型的一项,**代码里永远不再新增 if**。
