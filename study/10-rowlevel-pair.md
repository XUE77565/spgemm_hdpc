# 行级对拍终局:逐行 vs 逐行(2026-09-14,F2,双边全 hash + 双边 clock64 仪器)

> 一句话:**70,186 行逐行对逐行,我们赢 89.3%(均值比 0.55,中位 0.52 = 平均快 ~1.9×);唯一输带 = ht4096 档 4,437 行(1.34×,胜率 19%)。"hash kernel 不如 Ocean"在行级口径定谳为否;study/09 的 17-58% 是吞吐口径 + 档口行重错配的假象。read-first 无净赢,已回退。**

## 方法(用户钦定口径)

一个矩阵(F2,71505 行),双边全部走 hash(Ours:METHOD=adaptive 天然全 hash;Ocean:仅 487 行溢出走 denseIter),**两边 kernel 插同一根温度计**:
- 我方:`HASH_ROWTIME=path`(既有,docs/66)→ `row a_len flop est span ovf cycles`
- 彼方:新仪器 `ROWCYCLES=path`(ocean/kernels/AccumulatorHash.cuh + src/main.cu 补丁,hashNumericKernel 头尾 clock64 逐行,末次迭代值)
- 同单位(SM 周期)、同争用环境(各自 occupancy 配置 = kernel 设计的一部分)、同批行 → 逐行比值可判

可比行 = 70,186(排我方溢出 1319 + est>4096 边角)。

## 与前几轮口径的关系(重要)

- 行级(延迟,本篇):89% 胜,1.9× —— kernel 本体判据,**最纯**
- bin 级吞吐(study/06/09):F2 全家族 0.96×、逐档 0.81-1.58× —— 混入档口行重错配(我 est ×1.63 vs 彼 ×1.75,同 bin 名下我行更重)
