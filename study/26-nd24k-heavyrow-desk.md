## §3 位图经济学判决

**毛账(每重行,SMEM 事务粗单位)**:
- 乘积阶段:flop=184K 次。hash=每乘积探测链(1.3 LDS+CAS+F64 RMW≈2-3 串行 SMEM 往返,
  =short_scoreboard 11.16 的结构税根源);dense 位图=每乘积 1 次 offset atomicAdd val
  (**无探测/无 CAS/无链**)。省 ~1-2 往返×184K。
- **"dup 对位图免费"的精确边界(重要修正)**:免费只对 symbolic/count 阶段成立(1-bit 幂等);
  numeric 阶段 62 个重复 j 的值仍要 62 次 atomicAdd——dense 赢的不是免 dup,是**免探测链**。
- 提取阶段:dense 扫 span=65K 位(warp 并行 32 位/线程→~2K warp-ops)+值提取 2.7K;
  hash 走 est=2.7K 槽。**dense 多付 ~24× 空转扫描**(密度 4.2%)。
- 窗口化税:3 窗(val8)则乘积阶段每窗 B 段重定位;9-10 窗(7277)更重。
  B 行读(long_scoreboard)两边同付,不进差账。

**判决:可行,对拍值得跑**——但预期降温:旧假设"33% 密度位图碾压"不成立,真实形态是
"探测链省(乘积端)vs 空扫付(提取端)"的对冲,且 dup 62× 反而强化乘积端收益(每乘积的
探测链省得越多越好)。只有实测能定胜负。ocean 侧这些行彼送 hashNumeric(span 65K>彼
dense 最大档 7277,彼判据 range 拦死)——对拍=我方 dense 位图 vs 彼 hashNumeric 同行。

## §24 刀15 立项:SMEM-key + global-val 解耦累积(09-30 09:0x,用户"试架构级突破")

### 核心洞察

**F64 atomicAdd 的两种物理现实**:
- SMEM:CAST.SPIN 模拟 = 5-6 条/次 × 3.5 重试 = ~21 条指令/乘积(我们当前)
- **Global:原生 red.global.add.f64 = 1 条指令,fire-and-forget,无自旋**

### 架构设计

```
现行(刀6 态):
  SMEM 哈希表[ht](key+val 同居) → 每乘积:探测 + SMEM F64 CAS 自旋
  SMEM/块 = ht × 12B

刀15(解耦):
  SMEM 哈希表[ht](仅 key,col)  → 每乘积:探测(SMEM) + global F64 atomicAdd(原生)
  Global val[base+slot]         → 提取时从 global 读回
  SMEM/块 = ht × 4B(减 3×!)
```

### 预期收益定量

| 项 | 现行 | 刀15 | 依据 |
|---|---|---|---|
| 每乘积 SMEM 指令 | ~24(探测+自旋) | ~4(探测+1 global 发射) | 自旋 21→0 |
| SMEM/块 | 96KB(bin8) | **32KB** | val 移出 |
| accumulate | 80ms | **~30-40ms(估)** | 指令减 6×,global 原子 ~0.24ms 吞吐 |
| nd24k 系统 | 93ms(1.12×) | **~50-55ms(0.6-0.66×)** | accumulate 大降 |

### 正确性论证

1. 加法交换律:global F64 atomicAdd 的顺序无关 ✓
2. 精度:非确定性顺序与现行 SMEM 原子相同(值门用容差 1e-9) ✓
3. 地址:base+slot,slot<HT_P,base=行偏移,互不干扰 ✓
4. 清零:accumulate 前 cudaMemset(d_gval, 0, total_bytes) ✓

### 创新性定位(③)

这不是参数调优——是**解耦 key-value 存储**的新架构模式:
- key 在 SMEM(快探测、小脚印)
- value 在 global(原生原子、零自旋)
- 提取时一次 global 读回(per distinct 列,非 per 乘积)
