# study/38:管线精简——小阵快速路径(用户发现 10-10)

> 用户洞见:"我们的管线是不是太差了,不够精简?小阵可以换一个更轻量级的!"

## 一、核心发现:不是 kernel 输了,是管线输了

**行级证据**:公平窗时间加权 0.952(我们赢)——kernel 本身不比 ocean 慢。
**系统级证据**:GM 1.3895(我们输 39%)——管线开销吃掉了全部 kernel 优势。

### 333SP 逐相位对比(典型小中阵)

| 我们(17 相位) | ms | ocean(3 相位) | ms | 差距来源 |
|---|---|---|---|---|
| 估计器链(5 kernel) | 4.3 | Analysis(3 子项) | 0.7 | **MinHash 多 pass vs HLL≈0** |
| binning(路由核) | 4.2 | (排除在计时外) | — | **17 相位 vs 3 相位的架构差** |
| accumulate | 8.4 | Numeric(1 kernel) | 4.0 | 行级赢但系统级输(占用对消) |
| cnnz_scan + compact+sort | 6.8 | Epilogue(1 copy) | 1.4 | **排序贵 5×** |
| **合计** | **23.7** | | **6.1** | **3.9× 差距** |

### 全阵估计器成本模式(12 阵实测)

| 阵型 | 估计器占净窗 | 含义 |
|---|---|---|
| 小阵(c-43/msc/bloweybq) | **23-33%** | 纯税(无 retry 需要 MinHash 精度防) |
| 中阵(333SP/Si10H16/in-2004) | 10-12% | 半税 |
| 大阵(nd24k/c-64/rajat20) | 1-3% | MinHash 在救命(dup=62 防 retry 灾难) |

**MinHash 的价值是分人群的**:大/高dup 阵上防 retry(值回票价),小/低dup 阵上纯浪费。

## 三、修法:小阵快速路径(small-matrix fast path)

```
if (L0 判定: 小阵/简单阵) {
    快速路径(4-5 相位):
    1. 简单估计: flop 直接当 est(小阵不需要精确 distinct 估计)
       或: HLL 单 kernel(可选)
    2. 路由: 一行 if(全 hash 或 k7,不需要 compute_bucket)
    3. numeric: accumulate 一次
    4. 输出: 直接写(小输出不需要 compact+sort)
} else {
    完整管线(17 相位,现有):
    大阵需要精确估计 + 多武器路由 + 排序 → 精度值回票价
}
```

**这跟 L0 架构完美互补**:L0 v1 选配置(diter/k7 开关),L0 v2 选管线形态(全机器 vs 轻机器)。

## 六、风险与依赖

| 风险 | 应对 |
|---|---|
| 快速路径的正确性(跳过估计器→溢出) | 小阵 flop 小 → 溢出风险低;加 retry 兜底 |
| 跳过 sort → 输出无序 | 检查下游是否要求有序;k7 已天然有序 |
| L0 分类器不够准 | 管线形态是二值(全/轻),比 4-way 配置更易分类 |
| 337 屏还在跑 | 快速路径实现不依赖屏结果,可并行 |

## 七、与既有发现的关系

| 发现 | 关系 |
|---|---|
| 逐行成本≠系统成本(study/36) | 同一根因:管线效应在系统级,不在行级 |

| D6EXP 净负(study/36 D4) | 反证:逐行 overhead 每行都付,管线精简一次性付 |
