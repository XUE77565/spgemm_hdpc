## 一、部署架构(三层分工,定稿)

```
compute_bucket_kernel(每行):
  ① 现有静态 bin 结构不变:micro 武器(ESC/batch_s/ultra/sspan/largest/heavy)原路放行
  ② L0 全稠密规则(代码,非学习):est/n_cols ≥ 0.9 ∧ k7 谓词合法 → BIN_K7
     (物理:全稠密 C=位图主场;dense 回归器此域无训练样本=瞎外推,bloweybq 病理处方)
  ③ 争夺区(bkid∈{0-10 梯,13 diter,15 k7})∧ 非规则行 → 学生树三路裁决 {hash,dense,k7}
  ④ L2 证书兜底(k7 count 证书已在);学生输出仅改 bin 归属,不动管线机器
```

关键设计教训:**确定性规则不进学生**——单源现象(全稠密/微行)留出即失师(bcsstk32 旧病),
代码规则对任何新阵天然泛化。

## 二、部署语义检查的发现(D3① 最大产出)

LOO 考试被测量掩码遮蔽的两个教师外推病理,部署语义(无条件逐行决策)下现形:
1. **bloweybq 全选 dense**(实测 k7 快 4×):dense 回归器在 est 10-18K 全稠密特征区零训练
   样本 → 假低价。无回归风险(=现状)但拿不到 k7 赢面 → L0 规则(处方①)收回
2. **pre2 k7 低选**(662 vs oracle 153K):即挂账的"最后顽固边际"的量化;有界损失
   (153K 行×1.67× 中 25% 差价),v1 接受,证书不对称性(k7 错选安全自降级)是后续
   偏置选项的物理依据

### 定谳:D1 真值表成本=numeric 相 only,管线相位不对称未入模

- **dense 列漏 dense_count 精确计数相位税**(HAD_L1 刀2 判负在案:pre2 行走 diter →
  dense_count 25.5ms>整条 hash 路)——pre2 2.606 主因
- **c-64 14.854**:学生把 dense/cursor 主场行大规模改判 hash → c-64 宽 span 行在
  hash 梯=占用崖死区放大 15×(hash 行级本就 1.9× 慢于彼;真值表 hash 列同样只测
  numeric,未含 compact/est 摊账,且 c-64 hash 列是 H 臂强制测度)
- **方法论教训**:保真度代理门(学生复现教师 0.95)看不见这类错——教师本身就错在
  成本口径;A/B 真门一发放现。路线 B(以真门代代理门)此役实证正确

### 修复路径(D1 测量模型 v2,全 desk,零 GPU)

1. **相位摊账重标**:从 D/R 臂日志提取 dense_count/compact/retry 相位时长 → 按行
   摊入对应武器成本(dense+=dense_count/rows;hash+=compact+retry/rows;k7+=0——
   k7 的 count 即精确计数无额外税)

4. bloweybq 二阶税(纯 k7 阵跳 est 精修/heavy 单行免 accumulate 开张)另立小刀
