## 一、驱动发现(不可推翻的实验事实)

**逐行 kernel 成本 ≠ 逐行系统成本**——三轮 D3 A/B 实验证明(study/36 §六):
- pre2:逐行说 dense 赢(270K 行)→ 系统 +47ms(dense_count 相位爆发)
- c-64:逐行说 hash 赢(19K 行)→ 系统 +270ms(占用崖集体坍塌)
- 同一改判方向,相反系统效果——**逐行测量原理上看不见集体效应**

这不是"阈值没调对",是**测量粒度≠效应粒度**的物理问题:
- 集体效应(dense_count/占用/MEM 争用)的因果链在矩阵级
- 逐行 clock64 在 block 级——**原理上不可能**捕获跨 block 的集体效应

## 二、架构设计(从原理推导,非打补丁)

```
L0 矩阵级【新增,主刀】:
   输入:阵级特征(nnz/行统计量均值方差分位数/七武器人口占比)
   输出:管线配置 = {激活哪些武器, 各武器的阈值组}
   校准:用【系统级 TOTAL】(非逐行 cycles!)训练——每阵×每配置一发
   → 集体效应在这一层【全额包含】,因为标签就是含集体效应的系统总时间

L1 行级【降级为 L0 的执行者】:
   在 L0 选定的配置内,逐行微调(已有限制:hash↔dense 锁定,只做 k7 抢行)
   特征:已有 21 维
   → 这一层只做安全微调,不做跨界改判

L2 证书【已有】:
   k7 count 证书(数学背书) + hash 表大小证书
   → 预测错当庭降级,正确性不押注
```

**与 D6 的本质区别**:D6 的标签是逐行 kernel cycles(集体效应=0);L0 的标签是**系统总时间**(集体效应=100%)。

**与打补丁的本质区别**:不是修一个洞加一个护栏,而是把决策粒度对齐到效应粒度。

## 三、可证伪预言(如果理论错,我认)

1. **L0-only(不加 L1)应恢复大部分可达到的改善**——因为它捕获了集体效应
2. **L1 的增量只在多武器并存的阵上可见**——单武器阵 L1 无事可做
3. **L0-only vs 静态 的 gap > L0+L1 vs L0-only 的 gap**——系统级效应 > 行级微调

- 验证:LOO 按阵留一,报配置选择准确率
- 输出:L0 模型 + 每阵的"oracle 配置"真值表

### 第四步:51 阵广域屏(三级基线表)

## 五、论文叙事(此架构的故事)

1. **否定结果**(贡献 1):逐行成本模型有 85.7% 行级精度,但在系统级暴露集体效应盲区
   ——首次实验证明这一原理性极限,解释了为何学习型逐行调度在 SpGEMM 上无人做成
2. **架构**(贡献 2):两级 PVD——L0 系统级配置(集体效应在此可见)× L1 行级微调(安全域内)
   × L2 证书(正确性保证)——由否定结果驱动的架构设计
3. **预言验证**(贡献 3):L0-only vs L0+L1 的 gap 分解,证明系统级>行级
4. **评测基建**(贡献 4):462 万行真值表 + oracle-gap 三级基线 + 多种子协议
