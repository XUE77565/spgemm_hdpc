## 一、核心创新:多级自适应路由框架

### 1.1 问题定义

SpGEMM(稀疏矩阵乘法)没有"最优算法"——不同矩阵结构、不同行密度、不同
输出密度下,最优计算策略截然不同。现有方法要么固定用一种算法,要么做
整阵级的粗粒度选择:

| 现有方法 | 选择粒度 | 选择维度 | 局限 |
|---|---|---|---|
| IA-SpGEMM [2019] | 整阵 | 算法类型 | 无法处理阵内人口异质性 |
| Wang et al. [TACO 2025] | 整阵 | 算法参数 | 同上 |
| FlexSpGEMM [2026] | tile 级 | tile 大小 + 硬件路径 | ML 黑盒,内核变化时需重训 |
| **我们** | **阵级 → 子人口级 → 构建级** | **方法 × 变体 × 编译层** | 三级四维,测量出处 |

**核心主张**:路由决策必须在多个粒度同时做——
- **阵级**(哪个方法:hash/dense/merge3)
- **子人口级**(同一方法内,不同行群用不同内核变体)
- **构建级**(不同内核族用不同编译策略)

### 1.2 三级路由架构

```
┌─────────────────────────────────────────────────────────┐
│  第一级:方法调度(矩阵级)                                │
│  输入:n, nnz, 密度, skew, est                             │
│  决策:hash / dense / merge3                              │
│  实现:L0 自适应 dispatcher(预门 logit + 特征裁定)         │
├──────────────┬──────────────────┬───────────────────────┤
│  第二级A:     │  第二级B:          │  第二级C:              │
│  hash 内变体  │  dense 内变体      │  merge3 内变体          │
│  选择(人口级) │  选择(密度级)      │  选择(列域级)           │
│              │                  │                       │
│  est → bin   │  密度 → mode      │  列域 → 分桶            │
│  (10 个 bin) │  (direct/win/     │  (列域分桶打破          │
│  每 bin 选:   │   iterative)      │   归并串行瓶颈)         │
│  · 表大小     │                  │                       │
│  · 累积器类型 │                  │                       │
│  · 提取方式   │                  │                       │
├──────────────┴──────────────────┴───────────────────────┤
│  第三级:编译层调度(构建级,新增维度)                       │
│  内核族 × PTX 档位 → per-file 编译策略                     │
│  (compute_61 vs native sm_90,差 9-52%)                   │
└─────────────────────────────────────────────────────────┘
```

### 1.3 三个方法支柱的具体优化

**支柱 A:Hash 内核家族**

| 变体 | 适用人口 | 关键技术 | 效果 |
|---|---|---|---|
| hash_spa(LHT 梯) | est 128-16384(bin4-9) | 编译期常量折叠表长 + read-first 探测 | 主力内核 |
| hash_heavy | est 256-16384(bin4-9 重行) | warp 私有素数表 + B16 交织 + **有序直写** | 复活后达天花板 85% |
| hash_spa_batched | est 33-64(bin0 微行) | warp-per-row + 融合有序提取 | 微行巨阵主力 |
| bin9 素数档 | est 8192-16384(bin9) | 16253 槽素数表(195KB)替代 pow2 占用灾难 | 五阵 −28~−47% |

**核心技术:有序直写(Gv3v2)**——首个从并行 hash 累积器直接产出有序输出的算法:
```
warp 认领连续段 → __shfl_xor 位移 rank(5 轮) → popcount 位次
→ 跨段 smem 前缀 → 直写 tmp → 行内天然有序 → 下游免排序
```
效果:compact 从 counting-sort(38ms)降至 copy(11ms),消除了排序载体瓶颈。

**支柱 B:Dense 内核家族**

| 变体 | 适用人口 | 关键技术 |
|---|---|---|
| dense_mode | 密度 ≥15% 的小 n 阵 | 直接寻址,免探测免 CAS |
| dense_win_mode | 密度 ≥15% 的中 n 阵 | 窗口化直接寻址 |
| DIRECT5 | dense 行精确计数 | count pass 出精确 nnz → numeric pass 直写终态 |
| diter | 重行列窗口 | 迭代累积,窗口升序天然有序 |

**支柱 C:Merge3 内核**

| 技术 | 描述 |
|---|---|
| **列域分桶** | 按列域(而非行)分桶 → 不同列段并行归并 → **打破行级串行依赖** |
| 自适应桶边界 | 根据矩阵结构动态调整分桶 |
| 效果 | first100 微阵上 dispatcher→merge3 净赢(部署超 oracle,held-out +22.3%) |

### 1.4 编译层路由(新增维度)

**发现**:PTX(中间表示)级别影响内核性能达 9-52%,且影响正确性。
compute_61 是孤峰(compute_70/80 回落到原生水平)。

**方案**:per-file 多层编译——hash 内核文件用 compute_61→sm_90,
其他文件用原生 sm_90,模板参 TB_TAG 保证实例集不相交。

**效果**:hash 核 +9%(基线),hash_heavy 从死刑(+77%)复活为最强(65.9ms = 天花板 85%)。

### 1.5 路由决策的三代演进:手门 → 标定查表 → AI Router

**问题**:内核变体的选择门传统靠人工调阈值(手拍 if-else)。
在固定测试集上 if-else 永远可以调到"看起来很好"——但这是
**不可迁移的优势**(对着答案出题)。

**第一代:手拍门**(几周人工试错)
**第二代:标定型决策表**(470 阵标定 → 3×3×3 格 → 查表)
- 三层评估:训练集 GM 0.8077 / held-out 0.8808 / 泛化差距仅 +0.6%
- 价值:不是"更快"(等价于手拍),而是"有出处 + 可自动重生成"

**第三代:AI Router = 物理先验 + 学习残差 + 在线适应**(11-02 落地)

```
cost(option | matrix) = 物理闭式先验(x) + 线性残差修正(W·x+b)
决策 = argmin cost(带置信门控)
在线更新: 每次运行后 SGD 一步,内核变化自动适应
```

| 约束 | 我们的方案 | 替代方案的下场 |
|---|---|---|
| 数据极少(80 阵消融) | 每选项 ~15 参数,物理先验扛大头 | LightGBM/NN 饿死或过拟合 |
| 要外推(新阵更大/更密) | 物理公式训练范围外依然成立 | 树模型钳在叶值 |
| 内核会变(两天加 5 刀) | 在线 SGD 一步适应 | 离线训一次全部过期 |
| 部署成本 | host 14 次乘加,GPU 零改动 | 每块推理有载体税 |
| 冷启动 | 纯物理先验即合理路由 | 纯学习=随机 |

实测(11-02,80 阵消融 + 470 阵标定):
- 训练缺陷修复(bandit→监督式):val 准确率 40.9% → **60.3%**
- 选错时代价平均仅 **1.06×**(错误廉价)
- 置信门控部署:预测赢面 <5% 或特征未见过 → 跟随默认,
  **下限封死在"=手门",上限 = 方法层路由收益**

### 1.6 分层定谳:哪里需要路由,哪里不需要(11-02 独家测绘)

80 阵全消融(8 路由点 × 2 选项)的固定策略上限:

```
方法层(variant_combo):   固定最优仅 51%  ← 路由真主场,模型 60.3% 赢
bin45/csort:             固定最优 100%
compact_sorted/est_expand: 89-90%
bin9:                    60%(样本少)
block_ladder/flat/lht23:  ~50%(但差距 <0.5%,路由无意义)
```

**两个定谳**:
1. **子开关层默认≈oracle(差 0.7%)**——固定默认已把逐阵收益吃干净,
   任何模型在此层加不了速(算术必然:准确率 <100% 对全对固定规则必输)。
   该层贡献 = "证明无需路由,固化为机制"。
2. **选错代价分布极不均**:est_expand 悬崖 30×(溢出→retry 风暴),
   其余多数 ≤1.3×。Stakes 测绘本身是没人发表过的分析。

### 1.7 漂移:内核演化使路由决策作废(双二进制实测)

> ⚠️ 11-02 勘误:此前版本曾把"老标定 no_h69 在 51% 阵最优"解读为漂移天然
> 样本——**误读**。该数据实为三种消融变体(no_h69/no_h4555/no_all)互比
> 的最优分布(关一把刀总比关三把轻),有/无 bin9 人口分布一致,与漂移无关。
> 已撤回,以下为真实验设计。

**真漂移源 = 我们自己的双 TU 资产(真内核变化,非模拟减速)**:

```
旧世界 = spgemm_test_sm90: hash_heavy 原生 sm_90 编译(判死刑时代)
         → bin4/5 人口最优路由 = H45 off
新世界 = spgemm_test_c61:   hash_heavy compute_61 编译(复活时代)
         → bin4/5 人口最优路由 = H45 on
同一批阵,同一个开关,两个编译时代 → 最优路由翻面 = 漂移的实验室复现
```

**实验设计**(scripts/ai_drift_dual.py,14 个 bin45 人口阵 × 2 配置 × 3 二进制,
同会话同卡):
- Phase 1: 时代A(sm90,10-27)逐阵测 on/off → 旧最优 + 模型旧世界学习
- Phase 2/2c: 时代B(c61,10-27,编译层单变量)→ 时代C(生产,10-30,刀链落地)
- Phase 3: 带时代A先验的模型流入时代C观测流(3 pass),在线 SGD → 恢复曲线

**定稿结果**(results/drift_dual_experiment.json,11-02 artifact run):

```
臂                      A时代准确率   C时代准确率   C时间后悔
静态表(旧世界标定)         100%          14%        1.128x   ← 三天内核演化即崩
always hash_heavy         14%         100%        1.000x   ← 赌对方向的侥幸臂
always lht                86%           0%        1.130x
在线模型                  (训练)        86%        1.009x   ← 唯一跟着最优走的臂
```

- A→C 翻面 12/14;恢复曲线 pass1 57% → pass2 86% → pass3 86%
- **陈旧路由让全舰队慢 12.8%,在线模型只慢 0.9%**
- 工程教训入档:Phase3 首跑 29% 假阴性 = 特征标准化缺失
  (交互特征量级~170 → 先验 W·x 爆炸 → 两选项 err 双饱和 clip=5
  → 更新同步化、相对差冻结;与"指示器饱和掩盖机制"同族)

静态方法(IA/Wang/FlexSpGEMM)结构上做不出这个实验——他们内核不变;
我们有按需切换内核时代的多二进制 + 真实三天演化时间线。

**泛化实验**(held-out 40,预注册选样,11-02 定谳):
- 名单勘误:旧 heldout_72.txt = dispatcher 同池切分(72/72 全在 428 内),
  非真新阵;盘上真干净池 = data/train_disp 213 阵(0 进过任何 router 数据池),
  过封盘尺寸界(nnz≥1e5 或 dim≥1e4)余 40,等距选样规则先于结果封盘
- **结果(results/heldout_router_ab.csv)**:
  - 38/40 走 hash 路径(AI 决策点激活);**AI 门控翻面 0 阵**(全部保默认)
  - 配对比值 geomean 1.013,t=0.94 不显著 = 纯噪声(两配置执行完全相同 kernel)
- **定谳:下限证明,上限未测**
  - ✅ 未见阵上门控路由器 ≡ 手调默认,**零回归零开销**(保守设计兑现)
  - ⚠️ 上限(未见大阵上模型赢手门)未被本集测到——40 阵全为微阵
    (0.3-2.5ms,bin45/bin9 人口极小,决策点本身不存在);真测试需大阵,
    外部下载仍堵(403),如实报告为 limitation
- 与漂移实验互补成完整主张:未见+无证据 → 安全回退默认;
  有证据+内核漂移 → 在线适应并恢复(86%,后悔 1.009×)

## 二、与现有工作的对位

| 维度 | IA-SpGEMM | FlexSpGEMM | 我们 |
|---|---|---|---|
| 选择粒度 | 整阵 | tile | **阵 → 子人口 → 构建** |
| 选择维度 | 算法类型 | tile + 硬件路径 | **方法 × 变体 × 编译层** |
| 决策依据 | 启发式 | ML(黑盒,离线) | **物理闭式 + 学习残差(白盒)** |
| 内核变化适应 | 需重新调参 | 需重训 | **在线 SGD 自动适应(有漂移实证)** |
| 样本效率 | — | 需大训练集 | **80 阵即可(物理先验)** |
| 外推能力 | — | 树模型不外推 | **物理公式范围外成立** |
| 部署开销 | — | 推理载体税 | **host 14 次乘加,GPU 零改动** |

## 三、主张纪律(过度主张清单,11-02 钦定)

- ❌ "AI 比 if-else 准"——调优集上算术必输(固定默认≈oracle 已证)
- ❌ "首次行级路由"——SpMV hybrid 逐行 2009 年就有(Bell&Garland);
  我们可主张的是**签名维度 × 模型驱动 × 漂移实证**的组合空位
- ❌ "Regret 界 O(√T)"——贪心更新无探索项;要么加 ε-探索,要么
  降级措辞为"经验性适应"
- ❌ 暗示路由提升了 GM——0.8054 是刀的;路由支柱承担可维护性主张
- ✅ 可主张:自动化调优(几周人工 → 一次标定)、漂移适应(独家实证)、
  分层测绘(stakes 分析)、零载体税部署、方法层 60.3% vs 51%

## 四、总结

**一句话**:我们构建了一个三级(方法/变体/编译层)× 四维的自适应 SpGEMM
系统,在 428 阵上净赢最强竞品 19.5%(GM 0.8054);其路由层经三代演进
(手门→标定表→物理先验+在线学习),实现了"调优自动化 + 内核漂移自适应",
并以分层消融测绘了路由价值的分布(方法层 51% 固定上限 vs 子开关层默认即 oracle)。

**主创新点(扛旗)**:
1. 编译层发现(compute_61 孤峰 + 双 TU per-file 架构)
2. 算法刀链(0.8054:素数表/有序直写/LHT23 折叠/列域分桶)

**第二梯队(系统完整性)**:

5. 分层路由测绘(否定结果:子开关层无需路由)
