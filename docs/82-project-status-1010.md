## 二、我们发现了什么:五层递进的认知

### 第 1 层:kernel 层(已收口)

- **行级公平窗时间加权 0.952(我们赢)**——kernel 本身不输 ocean
- **占用物理定律**:寄存器悬崖+占用恒等式(1.34× 预测-实测闭环)
- **H100 硬件边界**:64-bit SMEM 原子全走 CAS 自旋(17 刀负结果全谱封棺)
- 重行输因 = 高 dup 自旋(硬件封棺)+ 低 dup 固定开张(k7 已收)

### 第 2 层:路由层——逐行调度的极限(否定结果)

- **D6 学习调度器**:LOO 一致率 85.7%,oracle-gap 2.17→1.06
- **但部署 A/B 三轮全崩**:D6EXP 在 51 阵屏净负 4.5%
- **定谳:逐行 kernel 成本 ≠ 逐行系统成本**(集体相位效应在行级不可见)
- pre2:逐行说 dense 赢 → 系统 +47ms(dense_count 爆发)
- c-64:逐行说 hash 赢 → 系统 +270ms(占用崖集体坍塌)
- **这个否定结果本身就是论文贡献**——解释了为什么无人做成学习型逐行 SpGEMM 调度

### 第 3 层:L0 矩阵级架构(正面突破)

- **两级 PVD**:L0 矩阵级配置选择(系统级 TOTAL 标签)+ L1 行级微调(安全域内)+ L2 证书
- **L0 oracle 51 阵验证**:GM 0.8818 → 新 GM **1.2253**(−11.8%)
- 核心洞察:**决策粒度必须匹配效应粒度**——集体效应只在矩阵级可见
- diter 在 17/33 阵上是毒药(Ge99 −77%/nd24k −57%)——关掉就赢
- k7 在 5 阵上大赢(bloweybq +23%/exdata +17%)但 10 阵上反输——需要矩阵级选择
- 337 全集屏正在跑(验证 L0 在全集上的 GM 拉动)

### 第 4 层:管线精简(最新发现,用户洞察)

- **17 相位 vs ocean 3 相位**:小阵 30-50% 净窗是管线税,不是 kernel 计算
- 估计器链:小阵 23-33%(MinHash 5 kernel vs ocean HLL ≈0ms)
- binning:小阵 5-15%;compact+sort:10-20%(比 ocean epilogue 贵 5×)
- **MinHash 的价值分人群**:大/高dup 阵防 retry(值回票价),小/低dup 阵纯税
- **修法 = 小阵快速路径**:17→4 相位(跳估计器+跳 binning+跳 sort)
- **预期 GM 拉动 −20~30% → 1.39 → 0.97-1.11(首次冲 <1.0 的现实路径)**

### 第 5 层:口径与系统效率

- T10 记分 = 相位和(排除 h2d/d2h,也不含相位间空隙)
- **墙钟暗物质** = cudaMallocHost 89%(pinned 重分配);USE_MEMPOOL 一开关 −88%
- ocean 的 D2H 病理(816-1499ms 回传)——按"每调用墙钟"我们 13× 赢(非算法贡献)
- 估计器效率差:我们 8.53ms vs ocean 0.69ms(333SP)——**12× 差距**
