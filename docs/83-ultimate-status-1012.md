## 三、我们学到了什么(五层递进认知)

### 第 1 层:kernel 层(已收口,2026-09 前)

- 占用物理定律(寄存器悬崖/占用恒等式,1.34× 预测-实测闭环)
- H100 CAS 自旋硬件边界(17 刀负结果封棺)
- 重行输因 = 高 dup 自旋(硬件封棺)+ 低 dup 固定开张(k7 已收)

### 第 2 层:逐行学习调度的极限(否定结果,10-08)

- D6 学习调度器:行级 85.7% 精度(D2 过门)
- **但部署后系统级净负 4.5%**
- **根因:逐行 kernel 时间 ≠ 逐行系统成本**(集体效应在行级不可见)
  - pre2: 逐行说 dense 赢 → 系统 +47ms(dense_count 爆发)
  - c-64: 逐行说 hash 赢 → 系统 +270ms(占用崖集体坍塌)
- **这是论文级否定结果**:解释了为什么无人做成学习型逐行 SpGEMM 调度

### 第 3 层:L0 矩阵级架构(正面突破,10-10)

- **L0 oracle 337 验证:GM 1.2740 → 1.1958(−6.1%)**
- 核心:整阵一发决策(选配置 A/B/C),零逐行开销
- 发现:**diter 在 149/337 阵上是毒药**——恒 A(全 hash)赢 4%
- k7 只在 bloweybq 型阵大胜(−27%),不能全局开

### 第 4 层:管线精简(发现,10-10~11)

- **17 相位 vs ocean 3 相位**:小阵 30-50% 净窗是管线税
- 估计器税:我们 9.5ms vs ocean 0.7ms(**14× 差距**)
- **dense_count 启动税:82ms(最差)** → 这就是 diter 是毒药的根因
- MinHash vs HLL:精度 vs 速度的取舍(双估计器=自适应选择,创新点)

### 第 5 层:口径与系统效率

- 口径对齐确认:binning 差仅 0.2%(差距是真实的)
- 墙钟暗物质 = pinned 重分配 89%(USE_MEMPOOL 一开关修好)
- ocean 的 D2H 病理(816-1499ms 回传)——按墙钟我们 13× 赢(但非算法贡献)
